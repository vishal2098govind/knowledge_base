After a message is polled by a consumer, it becomes **invisible** to other consumers
By default, the **message visibility timeout** is 30 seconds
This means that during this 30 seconds, the message has to be processed

And if we do so, that means that if the same or other consumers do a message request API call (ReceiveMessage request), then the message will not be returned during the **message visibility timeout window**
![[Pasted image 20260531100639.png]]
But, after the **message visibility timeout** is elapsed, and in the meantime that message has not been deleted from the SQS queue by the consumer who received it at the beginning of the **message visibility timeout** started, then message will be **"put back into the queue"** and therefore any other consumer or even the same consumer doing a ReceiveMessage API call will receive the message again, the same message as before

If we don't process a message within visibility timeout window, then it will be processed twice potentially, by two different consumers or twice by same consumer

So, if a consumer is actively processing a message, but knows that it needs to be a bit more time to process the message, because otherwise, it will go out of the visibility timeout window, there's an API called **ChangeMessageVisibility**.

So if a consumer knows that a message needs a bit more time to be processed, and we don't want to process that message twice, then the consumer should call **ChangeMessageVisibility** API to tell SQS not to make that message visible for now, indicating that the consumer needs bit more time to process this message

If it is set to really high value by default, say hours, and the consumer crashes, then it will take hours until this message appears again and becomes visible in the SQS queue again, and that will take lot of time
If it is set to something really low, like few seconds, if the consumer doesn't have enough time to process that message, for whatever reason, then it will be read many times by different consumers and we may get duplicate processing

So the idea is that visibility timeout should be set to something reasonable for our application, and the consumer should be programmed that if they know they need bit more time, then they should call **ChangeMessageVisibility** API to get more time and increase timeout of that visibility window
