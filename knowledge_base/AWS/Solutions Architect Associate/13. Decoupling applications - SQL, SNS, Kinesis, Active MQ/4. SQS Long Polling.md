Idea that the consumer is requesting messages from the queue and it can wait for messages to arrive, if, when we do a request **there are no messages for now in the queue**.

This is called **long polling**

**LongPolling** decreases the number of API calls made to the SQS, while increasing the efficiency and reducing latency of application because as soon any new message arrives to the SQS, it will be sent to the consumer

Thus, consumer will receive messages with least amount of lag.

So the long polling can be set between 1 second to 20 seconds (preferable)

Long Polling should be preferable to Short Polling

Long polling can be enabled at the queue level or at the API level using **WaitTimeSeconds** parameter
