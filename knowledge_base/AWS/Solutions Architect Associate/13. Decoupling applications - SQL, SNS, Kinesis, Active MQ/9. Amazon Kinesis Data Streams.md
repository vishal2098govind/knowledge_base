It's a service used to collect and store streaming data in real-time
The key-word to lookup for is really **"real-time"**

What is real-time data? – Data that is created and used on the spot

Features of Kinesis Data Streams:
- Retention between up to 365 days
- Ability to reprocess (replay) data by consumers
- Data can't be deleted from Kinesis – we've to wait for it to expire from a time perspective for it to get deleted
- Data up to 10 MiB (typical use case is lot of "small" **real-time data**)
- Data is going to be ordered if we send two data points with same partition ID
- Security:
	- At-rest KMS encryption
	- In-flight HTTPS encryption
- Kinesis Producer Library (KPL) to write optimized producer application
- Kinesis Client Library (KCL) to write an optimized consumer application

## Kinesis Data Streams – Capacity Modes
### Provisioned Mode:
**Choose** number of shards on stream

What is a shard?
- A shard is basically how big your stream is
- We can have one shard or thousands of shards if we want to
- The more shards we have the more throughput we're going to have inbound
- Each shard gets in-traffic 1 MBps or 1000 records per second
- Each shard gets out-traffic of 2 MBps

To send for e.g. 10,000 records per second or 10 MB per second, we need to scale to 10 shards

can scale manually to adjust number of shards over time to increase or decrease number of shards

Pay for each shard provisioned per hour

## On-demand mode:
No need to provision or manage capacity
Default capacity provisioned - 4 MB/s in-traffic i.e. 4000 records per second
Scales automatically based on observed throughput peak during last 30 days

Pay per stream per hour and data in/out per GB
