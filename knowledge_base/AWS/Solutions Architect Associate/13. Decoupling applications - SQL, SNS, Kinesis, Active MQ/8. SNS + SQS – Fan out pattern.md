Idea is we want a message to be sent to multiple SQS queues
If we send them individually to every SQS queue, there can be problems associated with it
- If application crashes in between
- If there are delivery failures
- If we add more SQS queues down the road


Thus, we want to use the fan-out pattern
Push once to SNS topic, receive in all SQS queues that are subscribers
![[Pasted image 20260531111245.png]]
This is a **Fully decoupled** model with no data loss

SQS gives 
- data persistence
- delayed processing
- and retries of work

Ability to add more SQS subscribers over time

Make sure **SQS queue access policy** allows for SNS to write

**Cross-Region Delivery**: Works with SQS queues in other regions

## S3 Events to multiple queues
![[Pasted image 20260531111910.png]]
There's a limitation of S3 event rules
- for **a combination** of **event type** and **prefix** - an object is being created we can only have **one s3 event rule**

Thus, if we want to send same s3 event to many SQS queues, we can use fan-out pattern

## AWS SNS FIFO Topic
SNS has FIFO capability i.e. ordering of messages in topic
This can only be subscribed by a SQS FIFO queue for now

Similar features as SQS FIFO
- **Ordering** by message group ID (all messages in the same group are ordered)
- **Deduplication** using Deduplication ID or content based deduplication

Both SQS standard and FIFO queues can be subscribers
Limited throughput (same throughput as SQS FIFO)

In case we need fan-out + ordering + deduplication
