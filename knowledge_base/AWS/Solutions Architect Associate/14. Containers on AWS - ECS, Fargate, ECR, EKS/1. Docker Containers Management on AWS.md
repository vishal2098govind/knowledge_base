## ECS
### EC2 Launch Type
![[Pasted image 20260531153815.png]]
ECS = Elastic Container Service
Launching Docker containers on AWS = Launching ECS Tasks on ECS Clusters

ECS Cluster is made of things
- With EC2 Launch Type, ECS Cluster is made of EC2 instances
- In that case, if we use an ECS Cluster with an EC2 launch type, we must provision and maintain infrastructure ourself i.e. EC2 instances
- Each EC2 instance must run ECS agent to register in the ECS Cluster
- On starting ECS Task, AWS is going to take care of starting or stopping containers
- New docker containers are going to be placed on the EC2 instances over time

### ECS Fargate Launch Type
![[Pasted image 20260531153828.png]]
Launch Docker containers on AWS
You do not provision infrastructure (no EC2 instances to manage)
It's all server-less
We just create task definitions
AWS just runs ECS tasks for us based on CPU or RAM we need

## IAM Roles for ECS
![[Pasted image 20260531160445.png]]
- EC2 Instance Profile for EC2 Launch type only
	- Used by ECS Agent 
		- Makes API calls to ECS Service
		- Send container logs to CloudWatch logs
		- Pull docker images from ECR
		- Reference sensitive data in Secrets manager or SSM parameter store
- ECS Task Role:
	- For EC2 launch type and Fargate launch type
	- Allow each task to have specific role per task
	- Task Role is defined in task definition of ECS service

## Load Balancer Integrations
![[Pasted image 20260531160455.png]]
Consider an ECS Cluster example with ECS Tasks running (containers) in EC2 Launch Type
Can run an application load balancer in front of it
Then users will be going to ALB and in backend to the ECS tasks directly

ALB supported and works for most use cases

NLB recommended only for high throughput or high performance use cases, or to pair it with AWS private link

Classic LB supported but not recommended - no Fargate support

## Data Volumes (EFS)
![[Pasted image 20260531160519.png]]
Mount EFS system onto ECS tasks to share some data
Works with both EC2 and Fargate launch types
Tasks running in any AZ will share same data in EFS file system

Ultimate combo = Fargate + EFS = serverless

Use cases:
- Persistent, multi-AZ shared storage for containers

Note: 
- S3 cannot be mounted as a File system on ECS tasks
