- Content Delivery Network (CDN)
- Anytime we see CDN, think CloudFront
- It improves the read performance by caching the content of website at different edge locations
- Since content is cached all around the world, user experience improves with lower latency
- Made of hundreds of points-of-presence globally, including edge locations and caches across the world
- By having content distributed globally, we get **DDoS** (Distributed Denial-of-Service) protection
- attack where all servers around the world are getting attacked at the same time
- Idea of CloudFront-
	- since our application is in worldwide
	- we're protected against these attacks, using something called **Shield** and **AWS Web Application Firewall**

## CloudFront Origins
- CloudFront has several origins, 
	- which are basically backends that we want CloudFront to connect to
- **S3 Bucket** as CloudFront origin
	- For distributing files and caching them at edge
	- For uploading files to S3 through CloudFront
	- Access between CloudFront and S3 is secured using Origin-Access-Control (OAC)
- **VPC** as CloudFront Origin
	- Can connect CloudFront to anything within VPC
	- For application within network on Amazon , within private subnets
	- Can be 
		- Private Application/Network Load Balancer
		- or EC2 instances
- Custom Origin (HTTP)
	- S3 website
	- or any public HTTP backend we want (like public ALB)

### CloudFront vs S3 Cross Region Replication
- CloudFront:
	- **Global** Edge network
	- Files are cached for a TTL (maybe a day)
	- **Great for static content that must be available everywhere**
- S3 Cross Region Replication:
	- Must be setup for each region you want replication to happen
	- Files are updated in near real-time
	- Read only
	- **Great for dynamic content that needs to be available at low-latency in few regions**
