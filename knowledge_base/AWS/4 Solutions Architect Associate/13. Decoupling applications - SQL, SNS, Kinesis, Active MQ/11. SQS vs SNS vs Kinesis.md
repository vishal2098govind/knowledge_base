## SQS
- Model where consumers "pull data" by requesting messages from SQS queue
- Data is deleted by consumer after being consumed so that no other consumers receive the data ever again
- Can have many workers (consumers) as we want
- They all work together to consume and delete all messages from the queue
- No need to provision throughput in advance, since it is a managed service
- Can infinitely scale very quickly
- Ordering guarantees only for FIFO queues
- Individual message delay capability

## SNS
- Pub-sub Model where producers "put data" for many subscribers
- All subscribers receive a copy of message being sent
- Up to 12,500,000 subscribers
- Data is not persisted
	- Data is lost if not delivered
- Can scale to 100,000 topics
- No need to provision throughput
- Integrates with SQS for fan-out architecture pattern
- FIFO capability for SQS FIFO
## Kinesis
- Standard pull-data mode
	- 2 MB per shard throughput
- Enhanced fan-out push-data mode
	- 2 MB per shard per consumer throughput
- Possibility to replay data since data is persisted within kinesis data stream
- Meant for real-time big-data, analytics and ETL
- Ordering at shard level
- Need to scale shard ourselves
- Data expires after X days
- Provisioned mode and On-demand capacity mode
