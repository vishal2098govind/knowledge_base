Can move between classes manually or using S3 lifecycle configurations

### S3 Durability and Availability
- High durability - 11 9's i.e. 99.999999999 of objects across multiple AZ
- i.e. if we store 10,000,000 (10 M) objects with S3, we can on average expect to incur a loss of single object once every 10,000 years
- quite durable
- Durability is **same for all storage classes** in S3

- Availability measures how readily available a service is
- Varies **depending on storage class**
- E.g. S3 standard -> 99.99 availability -> not available 53 minutes a year


#### S3 Standard - General Purpose
- 99.99% availability
- Used for frequently accessed data
- Low latency and high throughput
- Sustain 2 concurrent facility failures

- Use cases: Big data analytics, mobile/gaming applications, content distribution

#### Infrequent Access
- for data that is less frequently accessed 
- but requires rapid access when needed
- lower cost than standard
- **Standard - IA**
	- 99.9% available
	- Use case: Disaster recovery, backups
- **One Zone - IA**
	- High durability (11 9's) in single AZ
	- data lost when AZ is destroyed
	- 99.5% Availability
	- Use case: Storing secondary backup copies of on-premise data, or **data u can recreate**

#### Glacier Storage
Low-cost object storage meant for archiving or backup
Pricing: price for storage + object retrieval cost
- **Instant Retrieval**
	- Millisecond retrieval, great for data access once a quarter
	- Minimum storage duration of 90 days
- **Flexible Retrieval (formerly S3 Glacier)**
	- **Expedited** - retrieval speed - 1 to 5 minutes
	- **Standard** - 3 to 5 hours
	- **Bulk** - 5 to 12 hours
	- Minimum storage duration of 90 days
- **Deep Archive**
	- **Standard** - 12 hours
	- **Bulk** - 48 hours
	- Minimum storage duration of 180 days

#### Intelligent Tiering
- monthly monitoring and auto-tiering fee
- Moves objects automatically between access tiers based on usage
- There're no retrieval charges in S3 Intelligent-Tiering

- **Tiers**:
	- Frequent Access Tier (automatic): default tier
	- Infrequent Access Tier (automatic): objects not accessed for 30 days
	- Archive Instant Access Tier (automatic): 90 days
	- Archive Access Tier (optional): 90 to 700+ days (configurable)
	- Deep Archive Access Tier (optional): 180 to 700+ (configurable)

### S3 Express One Zone storage class
- High performance **single availability zone**
- Objects stored in a Directory Bucket (bucket in a single AZ)
- it is for objects stored in a "**Directory Bucket**"
	- bucket is available only in a single AZ
	- can choose which AZ
- Handles 100,000s requests per second with **single-digit millisecond** latency
- Up to 10x better performance than S3 standard (50% lower costs)
- High durability (11 9's) but lower availability since single AZ
- Co-locate storage and compute resources in same AZ (reduces latency)
- **Use cases**:
	- latency sensitive apps
	- data intensive apps, AI & ML
	- training, financial modeling, media processing, high performance computing
	- Best integrated with SageMaker Model Training, Athena, EMR, Glue ...

### Lifecycle Rules
- **Transition Actions** - Configure objects to transition to another storage class
	- Move objects to Standard IA class after 60 days of creation
	- Move to Glacier for archiving after 6 months
- **Expiration Actions** (auto deletion)
	- configure objects to expire(delete) after some time
	- e.g. 
		- to delete old versions of files if versioning is enabled
		- delete incomplete multi-part uploads
- Rules can be created for a specific prefix or specific object-tag (e.g. Department:Finance)

## Scenarios:
### Scenario 1
Your application on EC2 creates image thumbnails after profile photos are uploaded to S3
These thumbnails can be easily re-created, and only need to be kept for 60 days.
The source images should be able to be immediately retrieved for these 60 days, and afterwards, the user can wait for up to 6 hours.
How would you design this?
**Design:**
- Thumbnails –> 
	- can be on **One-Zone IA** (since they don't need to be durable - can be easily re-created)
	- Expiration Action after 60 days
- Source Images -> 
	- first 60 days - **Standard** 
	- **Glacier** Flexible Retrieval - Standard after that

### Scenario 2
SLA -> able to recover deleted S3 objects immediately for 30 days, although this may happen rarely. After this time, and for up to 365 days, **deleted objects** should be recoverable within 48 hours.

#### Design:
- Versioning + Transition action
- Transition action -> 
	- transition **non-current** versions of object to Standard IA
	- then transition to Glacier Deep archive after 365 days

### S3 Analytics - Storage Class Analysis
- Helps decide when to transition objects to right storage class
- only recommends for Standard and Standard IA
	- Does not work for One-Zone IA or Glacier
- Report updated daily
- 24-to-48 hours to start seeing data analysis
- Helps to improve lifecycle rules
