### S3 Use cases
- Backup and storage
- Disaster recovery - moving data across regions
- Archive - for cheap storage/retrieval later
- Hybrid Cloud Storage - including on-prem
- Application hosting 
- Media hosting - images, video etc
- Data lakes & big data analytics
- Software update delivery
- Static website hosting

### S3 Buckets
- S3 allows to store objects (files) in buckets (directories)
- Buckets are defined at **region level**
- S3 looks like a global service
	- even though the s3 list bucket interface shows all buckets across all regions
	- but buckets are created in a specific region
- Naming:
	- **Shared global namespace**
		- have a globally unique name (across al regions all accounts)
	- **Account Regional Namespace (new feature)**
		- allows for reuse of same bucket name across regions
		- internally aws would suffix with account name anyway
- Naming constraints:
	- no uppercase
	- no underscore
	- not an ip
	- must start with lowercase letter or number
	- must not start with prefix xn--
	- must not end with suffix -s3alias

### S3 Objects
- Objects (files) have a key
- The key is the full path of the file/object in the bucket
	- s3://my-bucket/**my_file.txt**
	- s3://my-bucket/**my_folder1/another_folder/my_file.txt**
- The key is composed of prefix + object name
	- s3://my-bucket/**my_folder1/another_folder/my_file.txt**
		- here prefix of the object = **my_folder1/another_folder/**
		- and object name = "**my_file.txt**"
- Internally There's no concept of folder or directories within buckets
	- although the UI will trick us to think folders do exist
- Everything in S3 is actually a key
- Objects have key -> full path
- Objects have values -> content of the file body
- Max object size = **50TB**
- if uploading more than **5GB**, must use **multi-part upload**
- Objects have meta-data
	- list of key-value pairs - system or user metadata
- Objects have version ID if versioning is enabled
