### Events:
- S3:ObjectCreated, Removed, Restore, Replication
- Object name filtering possible (\*.jpg)
- Use case:
	- generate thumbnails of images uploaded to s3
		- can create event notification and send to different consumers:
			- SNS topic
			- SQS queue
			- Lambda function
- S3 event notifications typically deliver events in seconds but can sometimes take a minute or longer
- Need IAM permissions for S3 Event notifications to work
	- for SNS topic example:
		- to make this possible, the SNS topic (a SNS resource) must have a SNS resource policy attached, allowing s3 service to use the SNS:Publish action on that SNS topic. Can make the policy more fine grained by only allowing a particular path of s3:
```json
{
	"Version": "2012-10-17",
	"Statement": {
		"Effect": "Allow",
		"Action": "SNS:Publish",
		"Principal": {"Service":"s3.amazonaws.com"},
		"Resource": "arn:aws:sns:us-east-1:<account-no>:MyTopic",
		"Condition": {
			"aws:SourceArn": "arn:aws:s3:::MyBucket"
		}
	}
}
```
- similarly for cases of SQS and lambda, they respectively need their corresponding resource based policies attached to themselves allowing S3 to perform SNS:Publish action on those resource
- Resource based policies are used instead of IAM roles in some resources, unlike EC2


### S3 Event notifications with EventBridge:
- We can enable a bucket to receive all S3 events into EventBridge, no matter whatsoever, all of them
- from event bridge we can send to over 18 different AWS services as destinations
- With EventBridge, we get more power:
	- **Advanced filtering** options with JSON rules (filtering on metadata, object size, name etc)
	- **Multiple Destinations** – e.g. Step Functions, Kinesis Streams, Firehose etc
	- **EventBridge Capabilities** – Archive Events, Replay Events, Reliable Delivery
